# 轻量 Markdown 编辑器设计规格

日期：2026-07-22

## 1. 产品定义

本产品是一款面向普通 Markdown 文件的轻量桌面编辑器。它的使用方式接近新版 Windows 记事本：用户可以双击、拖入或通过系统打开面板打开任意位置的文件，在标签页中阅读和修改，然后直接保存回原文件。

它不是 Obsidian 的替代品，也不要求用户创建仓库、知识库或项目。目标场景是处理不属于现有 Obsidian 仓库、也不适合导入该仓库的零散 Markdown 文档。

第一版以 macOS 为目标平台，架构保留对 Windows 和 Linux 的扩展能力。

## 2. 目标与非目标

### 2.1 目标

- 像记事本一样直接打开和保存任意位置的 Markdown 文件。
- 在编辑位置显示源码，在其他位置实时显示 Markdown 和 LaTeX 排版结果。
- 保持启动快、界面轻、操作简单，不让工程化功能干扰阅读和写作。
- 支持单文件、多标签页和可选文件夹浏览三种使用方式。
- 文件始终保持标准纯文本 Markdown，可被其他工具继续使用。
- 视觉风格参考 Obsidian Baseline 主题的克制、紧凑和低干扰设计语言。

### 2.2 非目标

第一版不提供以下功能：

- 双向链接、关系图谱、知识库索引或 Obsidian 仓库管理。
- 插件系统、主题市场或复杂的界面定制。
- Git 集成、终端、调试器、文档大纲等 IDE 功能。
- 云同步、账号系统或多人协作。
- 所见即所得的专有文档格式。

## 3. 技术路线

应用采用以下技术组合：

- Tauri：桌面外壳、窗口管理、系统菜单、文件对话框、文件读写和文件监控。
- React 与 TypeScript：界面组件和应用状态。
- CodeMirror 6：文本编辑、选择、撤销历史、键盘交互和增量装饰。
- [`@codemirror/lang-markdown`](https://codemirror.net/docs/ref/#lang-markdown) 与 [`@lezer/markdown`](https://code.haverbeke.berlin/lezer/markdown)：生成 CommonMark + GFM 增量语法树，驱动行内实时显示。
- KaTeX：行内与块级 LaTeX 公式渲染。

Markdown 语言层使用 `@codemirror/lang-markdown` 连接 CodeMirror 与 `@lezer/markdown`。解析器启用 `GFM` 扩展，以覆盖表格、任务列表、删除线和自动链接。LaTeX 使用自定义的 `@lezer/markdown` 行内与块级扩展生成公式节点，不另建一套全文 Markdown 解析器。CodeMirror 装饰插件通过 `syntaxTree(state)` 读取同一棵增量语法树，并根据选区决定显示源码标记还是渲染组件。

该选型的约束是：Lezer 语法树负责编辑结构识别，不负责生成 HTML；链接目标校验、KaTeX 输出和图片加载分别由独立组件处理。这样避免编辑视图与预览解析结果不一致。

选择 Tauri 是因为它使用系统 WebView，能保持较小的应用体积，同时可复用界面层支持未来的 Windows 和 Linux 版本。Electron 实现更直接但运行时偏重；纯 SwiftUI/AppKit 会提高未来跨平台迁移成本。

## 4. 应用界面

### 4.1 默认窗口

默认窗口是一张极简写作画布：

- 顶部保留系统窗口按钮、当前文件名、侧栏按钮、搜索和更多菜单。
- 顶部下方是纤细的文档标签栏，用于管理多个已打开文件。
- 中央是限制最大阅读宽度的编辑区。
- 不常驻活动栏、状态栏、文档大纲或属性面板。
- 单个文档时弱化标签栏，减少不必要的视觉层级。

### 4.2 文件侧栏

文件侧栏是可选的抽屉，而不是永久工作区：

- 直接打开零散文件时默认隐藏。
- 打开文件夹或用户主动点击侧栏按钮时显示。
- 提供文件浏览、新建、重命名、删除和名称筛选。
- 关闭侧栏后，编辑区恢复为纯写作界面。

### 4.3 启动与空状态

未打开文件时显示简洁空状态，提供：

- 新建文件。
- 打开文件。
- 打开文件夹。
- 最近打开的少量条目。
- 文件或文件夹拖放提示。

## 5. 文件交互

### 5.1 打开方式

应用支持：

- Finder 双击或“打开方式”。
- 将文件或文件夹拖入窗口。
- 应用内“打开文件”和“打开文件夹”面板。
- 通过最近项目恢复授权过的位置。

打开文件不会复制或导入内容。文件夹也不被转换为项目或仓库。

### 5.2 标签页

- 一个窗口可以打开多个 Markdown 文件。
- 标签显示文件名、未保存状态和关闭按钮。
- 支持鼠标与快捷键切换、关闭和重新打开最近关闭的标签。
- 重复打开同一路径时聚焦已有标签，不创建副本。
- 重启应用后恢复上次的标签列表；未保存内容通过独立恢复副本恢复，不伪装成已写回磁盘。

### 5.3 保存

- `⌘S` 将当前纯文本缓冲区写回原路径。
- 新文件或只读位置使用“另存为”。
- 关闭含未保存修改的标签或窗口时，提供保存、放弃和取消。
- 写入失败时保留缓冲区，并提供重试或另存为。
- 保存保留原文件的 UTF-8 BOM 状态和 LF/CRLF 换行风格。

### 5.4 权限与分发

权限体验遵循普通桌面文本编辑器：

- 应用访问用户主动打开、拖入或明确选择的文件和目录。
- 正式 macOS 版本通过 [Developer ID](https://developer.apple.com/support/developer-id/) 签名，启用 Hardened Runtime，经 Apple 公证后以 DMG 或 ZIP 发布到 GitHub Releases。
- 第一版不启用 App Sandbox，因此不使用面向沙盒持久访问的[安全范围书签](https://developer.apple.com/documentation/professional-video-applications/enabling-security-scoped-bookmark-and-url-access)；最近文件和文件夹只保存普通路径，实际读写仍受当前用户权限及 macOS 隐私控制约束。
- 未签名或临时签名构建仅用于本地开发，不作为面向普通用户的正式安装包。
- 如果未来进入 Mac App Store 或主动启用 App Sandbox，再将安全范围书签作为独立兼容层加入，不改变文档核心接口。
- Tauri 命令只暴露完成文件操作所需的最小能力，不允许界面层任意调用系统命令。

### 5.5 外部变更

- 文件没有本地修改时，检测到磁盘变化后自动重新载入。
- 文件存在本地修改时，提示用户重新载入磁盘版本、保留编辑版本或另存为。
- 文件被移动或删除时保留当前缓冲区，并提示另存。
- 不在用户不知情的情况下覆盖本地修改或外部修改。

## 6. Markdown 实时编辑

### 6.1 核心原则

文档模型始终是纯 Markdown 文本。渲染结果只存在于 CodeMirror 显示层，不参与文件序列化。

数据流为：

`磁盘文件 → 纯文本缓冲区 → Markdown 增量解析 → CodeMirror 装饰与 KaTeX 组件`

保存只执行反向的纯文本写入，不从渲染 DOM 生成 Markdown。

### 6.2 行内实时显示

- 光标不在某个语法结构中时，隐藏相应 Markdown 标记并显示排版结果。
- 光标进入标题、强调、链接、代码或公式等结构时，该结构恢复为可编辑源码。
- 光标离开后重新显示排版结果。
- 选区跨越多个结构时，优先保证选择和复制行为稳定，不强制隐藏标记。
- 提供纯源码模式快捷开关，便于处理特殊或解析失败的文档。
- 撤销、重做、复制、粘贴和查找替换始终作用于原始文本。

### 6.3 查找与替换

第一版直接使用并轻量换肤 CodeMirror 6 的默认搜索面板，不实现跨文档搜索：

- `⌘F` 在当前活动文档中打开查找。
- `⌥⌘F` 在当前活动文档中打开查找与替换。
- 支持区分大小写、全词匹配和正则表达式开关。
- 支持查找上一个、查找下一个、替换当前匹配和替换当前文档全部匹配。
- 搜索始终针对原始 Markdown 文本，因此可以找到当前被行内渲染隐藏的语法标记。
- 切换标签后搜索范围切换到新活动文档，不自动跨标签汇总结果。
- 文件夹全文搜索和跨标签替换不属于第一版范围。

### 6.4 第一版语法范围

- 标题和段落。
- 粗体、斜体、删除线。
- 有序列表、无序列表和任务列表。
- 引用与分隔线。
- 行内代码、围栏代码块和基础语法高亮。
- 普通链接与图片。
- GitHub 风格表格。
- `$...$` 行内公式与 `$$...$$` 块级公式。

输入 `# `、`- `、`1. `、`> ` 等常用前缀后，编辑器按对应 Markdown 结构继续输入。

### 6.5 LaTeX

- 使用 KaTeX 渲染受支持的 LaTeX 语法。
- 公式正确时显示排版结果。
- 公式不完整或解析失败时保留源码，并显示非阻塞错误提示。
- 公式错误不影响文档其他部分的编辑、保存或渲染。

### 6.6 图片

- 相对路径以当前 Markdown 文件所在目录为基准。
- 支持本地绝对路径和网络图片显示。
- 从剪贴板粘贴位图时，每次都打开系统保存面板；默认目录为当前 Markdown 文件所在目录，默认文件名由日期时间生成，用户确认保存后才插入路径。
- 当前 Markdown 文档尚未保存时，图片保存面板使用系统最近位置；取消面板时不创建文件，也不改动文档。
- 将已有图片文件拖入编辑器时不复制图片，直接插入指向原文件的路径。
- 当图片能从当前 Markdown 文件目录表达为相对路径时插入相对路径，否则插入本地绝对路径。
- 第一版不自动创建附件目录，也不改写已有图片路径策略。

## 7. 视觉与主题

视觉参考为 MIT 许可的 [Obsidian Baseline](https://github.com/aaaaalexis/obsidian-baseline)，但不复制 Obsidian 的产品结构。

设计原则：

- 使用 Inter 作为界面字体，正文与界面字体分离。
- 使用克制圆角、低对比边界、紧凑控件和清晰留白。
- 提供 Baseline Light、Baseline Dark 和跟随系统三种外观模式。
- 默认展示风格为 Baseline Dark；“跟随系统”作为可选模式。
- 动效只用于侧栏、菜单和状态变化，并遵循系统“减少动态效果”设置。
- 偏好设置只保留正文大小、行高、最大宽度、字体与主题等少量选项。

## 8. 状态与恢复

应用仅保存必要的本地状态：

- 窗口位置与尺寸。
- 主题和少量编辑偏好。
- 最近打开的文件与文件夹。
- 上次打开的标签列表。
- 未保存文档的临时恢复副本。

应用不建立全文知识库索引。临时恢复数据在文档成功保存并关闭后清理。

## 9. 性能与降级

性能验收的最低参考机为 Apple M1、8 GB 内存和本地 APFS SSD，使用项目支持范围内的稳定 macOS 与 Release 构建。测试报告记录具体芯片、内存和系统版本。关闭开发者工具及其他调试开销，每项连续测量五次并取中位数；输入延迟另记录第 95 百分位。

内部参考值：

- 热启动：从启动进程到空白窗口可输入，中位数不超过 1 秒。
- 首次冷启动：从启动进程到空白窗口可输入，中位数不超过 2 秒，不包含 macOS 首次 Gatekeeper 验证时间。
- 常规文档：1 MiB 或 20,000 行以内启用完整行内渲染，打开时间不超过 1 秒，连续输入的输入到绘制延迟第 95 百分位不超过 32 毫秒。
- 大文档：超过 2 MiB 或 50,000 行时自动进入轻量模式，只装饰可见区域并暂停非必要图片预载；界面显示可退出的“轻量模式”提示。
- 压力文档：10 MiB 或 100,000 行的 UTF-8 文档在轻量模式下打开时间不超过 3 秒，输入到绘制延迟第 95 百分位不超过 50 毫秒，保存到本地 SSD 不超过 1 秒。
- 文件侧栏：包含 10,000 个目录项的文件夹只加载展开节点；首层列表可交互时间不超过 1 秒。

实现规则：

- Markdown 解析随编辑增量更新，不在每次输入后重建全文 DOM。
- 文件树按需加载，不递归预读整个目录内容。
- 图片和公式组件只在可见区域及邻近缓冲区域创建。
- 主题动效不阻塞输入，并能随系统设置关闭。
- 自动化性能测试超过参考值时产生报告并阻止发布构建；不同硬件的绝对结果可记录，但发布基线以指定环境为准。

## 10. 错误处理

- 打开失败：显示原因并允许重新选择文件。
- 编码不受支持：不以错误编码覆盖原文件，提示以 UTF-8 方式另存。
- 保存失败：保留缓冲区和恢复副本，提供重试与另存为。
- Markdown 解析失败：局部回退为源码，不阻断整个文档。
- LaTeX 解析失败：保留公式源码并局部提示。
- 文件冲突：让用户明确选择磁盘版本、编辑版本或另存版本。
- 应用异常退出：下次启动提供恢复入口。

## 11. 测试与验收

### 11.1 单元测试

- Markdown 结构识别与行内装饰范围。
- LaTeX 成功、失败与不完整输入。
- GFM 扩展节点与自定义 LaTeX 节点的增量解析。
- 文件状态、未保存标记和标签去重。
- UTF-8 BOM 与 LF/CRLF 保留。
- 外部修改、删除和移动状态转换。
- 恢复副本创建与清理。

### 11.2 组件测试

- 光标进入与离开语法结构时的源码/渲染切换。
- 跨结构选择、复制、粘贴、撤销和重做。
- 标签打开、切换、关闭与恢复。
- 单文档大小写、全词、正则查找以及单个/全部替换。
- 文件侧栏展开、收起、筛选和文件操作。
- 主题切换与减少动态效果。

### 11.3 桌面端到端测试

- 通过 Finder、拖放和打开面板打开文件。
- 新建、保存、另存为和关闭确认。
- 打开文件夹并从侧栏切换文件。
- 外部程序修改、移动或删除当前文件。
- 应用异常退出后的会话与未保存内容恢复。

### 11.4 人工验收材料

使用包含以下内容的真实中英文文档验收：

- 长段落与多级标题。
- 嵌套列表、任务列表和引用。
- 宽表格与长代码块。
- 本地图片、网络图片和失效图片。
- 行内公式、块级公式和错误公式。
- 大文件与快速连续输入。
- 1 MiB 常规文档、2 MiB 轻量模式边界和 10 MiB 压力文档。

## 12. 第一版完成标准

第一版完成时，用户能够：

1. 在 macOS 上安装并启动应用。
2. 从任意位置打开、拖入、新建和保存 Markdown 文件。
3. 在一个窗口的多个标签页中切换文件。
4. 可选打开文件夹并使用可收起侧栏浏览其中的 Markdown 文件。
5. 在同一编辑画布中完成 Markdown 与 LaTeX 的源码编辑和实时排版。
6. 在保存失败、外部修改或异常退出时不丢失未保存内容。
7. 在 Light、Dark 和跟随系统模式间切换，并获得一致的 Baseline 风格体验。
8. 在当前文档中完成大小写、全词和正则查找替换。
9. 在量化性能基线内打开、编辑和保存常规与压力文档。
